# Current vs future state guidance

Use this reference to keep state modeling practical.

## Current state should describe
- how work actually happens today;
- main actors and handoffs;
- bottlenecks, delays, rework, exceptions, and workarounds;
- data or decision pain points;
- where evidence is strong vs weak.

## Future state should describe
- target business behavior or operating model;
- clearer ownership, flow, visibility, or decision quality;
- expected business outcomes or success signals;
- critical dependencies required to make the state viable.

## Common mistakes
- describing the future state only as a tool purchase;
- calling aspirations a current-state fact;
- skipping constraints, adoption risks, and operating implications.
