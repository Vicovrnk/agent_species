# Traceability relationships

Use traceability to preserve analytical lineage, not paperwork volume.

## Common useful links
- business goal -> requirement
- policy or business rule -> requirement
- stakeholder concern -> requirement
- requirement -> dependency
- requirement -> downstream delivery item
- requirement -> risk or control consideration
- change request -> impacted requirement(s)

## Guidance
A trace link is useful when it helps answer one of these questions:
- why does this requirement exist?
- what will this change affect?
- what becomes invalid or orphaned if this item moves?
- what approval or control path is relevant?
